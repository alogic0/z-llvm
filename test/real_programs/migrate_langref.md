# Language-reference migration corpus

The [manifest](migrate_langref.json) compiles the existing 457-line
`tools/migrate_langref.zig` from the repository identified by
[`ziglang_pin.txt`](../../docs/evidence/ziglang_pin.txt). The program is not
copied or patched. Its source hash and Git contents are checked before running;
the source, manifest, runner and compiler identities are rechecked afterward.

Each executable receives the same 29 cases in fresh working directories. Files
listed in `input_files` are created there; `args` uses relative paths. The
`out` directory starts empty. The oracle requires ordinary process completion,
exact exit status and streams, and the exact set and bytes of every output
file. Inputs must remain unchanged. Reference and local observations are kept
separately and compared with the oracle and with each other.

The expected files were specified from the tool's documented markup and source
behavior before local execution. They are not snapshots generated by LLVM:

- Plain text and non-code tags are preserved byte for byte. A trailing ordinary
  opening brace remains text; UTF-8 is handled as document bytes.
- A `code_begin` / `code_end` block becomes one `code` reference followed by a
  newline. Its source loses the initial newline and surrounding ASCII whitespace,
  then receives two newlines and the selected metadata comments.
- All ten code kinds have explicit expected comments. Repeated mode and target
  directives use the last value; link objects and additional options retain
  insertion order. The upstream spelling `additonal_option` is intentional.
- The list-growth case supplies 128 link objects and 128 additional options.
  Other cases extract 96 named blocks, copy a document of more than 100 KiB,
  and extract 2,048 source-comment lines. These cross list capacities and file
  writer buffers using runtime input.
- Missing input and duplicate output names exercise filesystem failures.
  Unknown kinds/directives, a truncated tag, and a missing end marker exercise
  parser errors. Error locations are one-based. The truncated name starts at
  column 18. The upstream EOF location has no excerpt because its `line_end`
  remains zero. Partial files are checked: flushed earlier source files remain,
  while a short unflushed document is empty after an error.

Both compiler routes use single-threaded startup and disable error-return traces
to make deliberate error observations exact. This corpus does not validate
panic stack traces, concurrent I/O or allocation failure injection.

Observation controls reject false completion, changed exit status, changed
stdout/stderr, an extra file, and (when an output exists) changed or missing
file contents. They test the observer; they are not compiler mutations.

Run the corpus with:

```sh
zig build zig-input-program -- --output-root=tmp/zig-input-run
```

The same manifest is mandatory in the integrated executable gate. Compilation
profiles and ownership sidecars are retained per mode; emission counts do not
claim that every emitted definition executed.
