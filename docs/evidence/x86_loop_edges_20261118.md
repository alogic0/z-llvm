## Direct stores to PHI slots

The starting revision is `478a57cc`, with production compiler source from `5d6b921e`. The first PHI patch (A1, `45fc57ad`) skipped a temporary spill when every i32 PHI source was a register with a single visible use. It removed both temporary spill and reload sequences on the scalar replacement of aggregates (SROA) form of the loop. On the original IR it reproduced the 127-byte production kernel byte for byte. The parser found one use of the new index. The raw `align 4` field on the allocation was the only opaque field in the function. Removing that single attribute preserved the baseline object byte for byte and made the first candidate store directly. The original and alignment-only disassemblies and the per-instruction operand census are preserved. A diagnostic program first failed to compile because it indexed a Zig tuple at runtime. The corrected program used a homogeneous array.

The second PHI patch (A2, `8ea76782`) accepts a complete literal power-of-two alignment in the selector's use walk. It counts the allocation's typed count, visits instruction metadata and declines other opaque fields. The existing live-register spill runs before edge lowering. Each admitted edge has ordinary i32 register sources and final spill slots. Every source has a single typed use and is distinct from the PHI result identities. Mixed and slot-sourced edges use the existing snapshot logic. On the production backedge, `addl $1, %eax` now leads directly to `movl %eax, (%rsp)` and the jump. In promoted IR, the accumulator in EDI and index in EAX go to two distinct final slots.

Within each release mode, both arms used identical IR and driver bytes. All 272 finite-trip results and the timed digest matched for the original and promoted loops. The swap and extra-use fixtures matched two separate arithmetic oracles over 272 inputs apiece on baseline, candidate and LLVM. The two deliberately broken inputs changed 254 and 256 rows. Focused Debug and ReleaseFast tests exercised both final stores, zero and many trips, arithmetic wrap, a live seed, the original aligned loop, trailing attributes, metadata and structured or opaque allocation counts. The independent reviewer matched 2,240 observations per direct, Fast and Small route.

## Branching directly on the equality flags

The corrected comparison patch (B2, `47e0f4b0`) is incremental on that exact PHI source. It handles a named i32 equality whose two named operands feed a comparison immediately before the block's conditional branch. The Boolean has one fully visible typed use. Successor PHIs retain their materialized branch path. After boundary preservation, the state owner checks the final machine instructions for CMP and SETE and checks both instruction indices against the recorded flags definition and use. It also checks the named binding against the current i1 EAX occupant. It changes the flags consumer in place to JE and expires that Boolean binding. Other comparisons, extra uses, intervening flag writers and successor PHIs retain the original path.

The B1 compiler had already emitted the direct branch and matched 425 cases per function on the five-function fixture. Its timings were never started. The corrected compiler has its own 680-member source map, build, emitted programs, native checks and timing records.

On the original production loop, corrected compiler `8374c281` emits `cmpl %ecx, %r8d` immediately followed by `je`. It removes the sequence that materialized the Boolean in EAX and tested it again. Both local modes reduce loop text from 119 to 111 bytes and the stripped executable from 237,496 to 237,480 bytes. All four other workloads have identical program objects and timed executables on their corresponding routes. Every LLVM reference image is byte-identical across arms. The read-only data sizes are unchanged throughout.

The five-function control checks the admitted equality and swapped operands, an intervening addition that writes flags, another use of the Boolean, and a successor PHI. For each function, 141 equal and 284 unequal inputs match an independent arithmetic oracle. The LLVM reference matched all 2,125 function observations. Each local compiler matched those observations on each of the direct, Fast and Small routes. Four deliberate corruptions each failed for the intended reason. Primary review independently matched 2,240 observations on each local route. The object check finds one adjacent CMP/JE in each of the two admitted functions and one SETE in each of the three exclusions. The 9 focused tests passed in Debug and ReleaseFast.
