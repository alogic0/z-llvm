# Unchanged Zig program with runtime input

Status: complete at `9cc31c38`; all 17 integration gates pass.
Successor to the accepted
[compiler selection performance plan](2026-11-06-compiler-selection-performance.md).

## Intended result

Compile and execute the pinned Zig repository's existing
`tools/migrate_langref.zig` without changing its source. This 457-line maintenance
tool reads language-reference markup, mutates tokenizer and directive state,
grows allocated option lists, extracts named source files, and reports parse
and filesystem errors. It adds real Zig frontend coverage beyond the fixed
examples and the separate C JSON parser corpus.

Use the existing Zig revision pin and authenticate the program's source against
both its SHA-256 and Git bytes. Compile once per Fast, Safe and Small mode using
the existing local optimizer/object hook and pinned LLVM reference. Keep the
single-threaded startup and libc/compiler-rt link contract explicit. Disable
error-return tracing in both routes so deliberate errors have exact portable
diagnostics; panic/stack-trace behavior is outside this corpus.

## Implementation order

1. Qualify the unchanged tool with the pinned frontend. Freeze a corpus with
   independently specified exit status, stdout, stderr, and complete output-file
   contents. Cover empty/plain text, preserved markup, all extraction kinds,
   mutable options and mode changes, many extracted blocks, list and buffer
   growth, malformed directives, missing inputs, and duplicate output names.
   Expected results must not be generated by the reference executable.
2. Extend the existing unchanged-program runner with per-case argv, isolated
   working directories, input files, and exact output-tree observations. Keep
   the existing single-observation manifests working. Authenticate the manifest
   and source before and after execution, retain each observation, and compare
   both implementations with the independent oracle and with each other.
3. Add negative controls for completion, status, streams, file contents and
   missing/extra files. These mutate observations, not compiler implementations.
   Check path containment and case isolation. Integrate the workload into the
   permanent executable gate without changing existing population definitions.
4. Reproduce any backend failures on retained IR and repair shared compilation
   behavior. Add focused executable regressions for demonstrated failures;
   preserve normalization, transfer, ownership and rollback contracts. Do not
   patch the workload or add function-name exceptions to make it pass.
5. Record phase/function/legalizer profiles and ownership for all three modes,
   including independent ownership replay. Run applicable unit, policy,
   structural, ABI, route and readiness checks, then all 17 integration gates
   against a frozen source snapshot. Publish evidence and promote the accepted
   checkpoint only after the complete run passes.

## Acceptance and limits

Every input must match its independent expected observations and its LLVM
reference in all three modes. Report program modes, input/mode pairs, emitted
definitions and observation controls separately. Compilation profiles describe
this workload's compiler cost; they do not establish generated-code performance
or execution of every emitted definition. Keep all existing Fibonacci, C corpus,
compiler-core and native regression populations required.

Retain accepted evidence and compilers, authenticated AIR, diagnostic worktrees,
and the original thirteen scratch probes. Create no archives. The full gate
still requires 32,949,672,960 bytes free before starting and a 24,359,738,368-byte
reserve during execution. The task began with only about 14.3 GB free. Audited
project cleanup and additional filesystem activity subsequently satisfied
admission; the completed gate retained the original thresholds.

## Completed checkpoint

Steps 1–5 are complete. The unchanged program passes all 29 cases in Fast,
Safe and Small: 87 input/mode pairs and 603 rejected observation mutations.
Safe exposed three shared backend gaps: runtime pointer arguments to boolean
calls, integer `undef` atomic RMW operands, and popcount calls without optional
range annotations. All are repaired with executable regressions; the workload
source remains unchanged. See the [evidence and upstream mapping](../evidence/zig_input_program.md)
and [full acceptance record](../evidence/zig_input_program_acceptance_20261106.json).

Step 5 retains profiles and identical independent ownership replay for every mode.
Debug and Safe unit/policy tests, structural, captured-object, ABI, compilation
routes, readiness and three-mode Fibonacci pass. The frozen 2,967-file source
snapshot passes all 17 integration gates and 1,475 canonical log records.
All 36 compiler-core records match prior fresh execution; the cohort remains
100 lowered/emitted/linked and nine executed functions per mode. All 45 native
populations pass 1,767,660 local observations against 883,830 references.

The [project-only cleanup](../evidence/project_space_cleanup_20261106.json)
removes 7.24 GB of allocated data across three audited intervals, including
185.56 MB of build cache regenerated during full validation. Current AIR,
compilers, prior evidence, diagnostic worktrees and all thirteen original probes
remain. No archives were created. Final recorded free space is 53.30 GB.
The retained profiles support subsequent compiler-performance investigation;
this milestone does not claim generated-code optimization quality or execution
of every emitted definition.
