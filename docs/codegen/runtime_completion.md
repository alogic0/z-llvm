# Runtime completion contracts

The [compiler-object and self-rebuild checkpoint](../evidence/compiler_object_self_rebuild.md)
accepts the original **455/455 runtime definitions** with complete local object
emission, independent ELF/event/owner audits, linked execution and cumulative
validation. All 387 preceding selections and owners are preserved. Both fresh
runtime captures from the unchanged build and self-build also pass independent
audits and match the original allocated section, symbol and relocation graph.

The additional integer forms use existing checked typed homes and transfer
transactions. Pair widening accounts for live incoming physical words in the
allocation plan. Pair comparisons stage simultaneous inputs through the frozen
value-use interface. The exact unsigned `divq` assembly returns quotient and
remainder through the existing two-word carrier; its RAX/RDX/RCX transfers are
planned together. Nearby assembly templates and envelopes remain unsupported.
Scalar signed/unsigned comparisons return -1, zero or one in i32 for i32/i64
operands. i128 trailing-zero count returns 128 at zero; unsigned min/max retain
both words. Constant i128 funnel shifts normalize modulo 128 and avoid shifts
by 64 within a word. Variable i128 funnel counts remain closed.

Floating vectors expand into bounded scalar lanes when existing native paths
cannot represent the graph. Existing native casts retain their path. Packed
`<2 x float>` arguments/returns use the low 64 bits of XMM, with raw double
carriers in the private graph. Reinterpretation preserves NaN payloads and
signed zeros. Ordinary exact lane stores preserve neighboring memory; volatile,
atomic, unsupported vector ABIs and explicit vector layout overrides stay closed.
Half copysign transfers raw sign bits. Half maxnum promotes its representable
operands to float and narrows the result. A half-add scratch snapshot preserves
a simultaneous final-use XMM0 operand through the existing authority.

LLVM `byval(x86_fp80)` pointer parameters describe aligned incoming stack values.
Private 128-bit memory carriers and owned 16-byte copies preserve pointer uses
inside the function. Callers load and place the same stack values. The source
signature remains immutable. Native f80/i128 allocation and alignment are checked;
overalignment and unsupported attribute envelopes are rejected. Extended maxnum
uses the declared GNU libm `fmaxl`/`fmaxf128` providers with recursion checks.
Normalized constant-table indices retain proved range/parity through bounded
masks, casts, shifts and selects; adjacent unproved indices remain closed.

Resolved `weak_odr` ELF aliases retain weak binding, visibility, target address,
type and size for defined functions and ordinary initialized objects. TLS targets
and ordinary `weak` aliases retain their rejection boundary. Undefined LLVM
intrinsics fail the whole-compiler object contract instead of earning completion.

`runtime_frontier` is generated by `tools/generate_runtime_frontier_canary.zig`.
Its 852 observations cover the new carriers, caller/callee boundaries, live
values and store guards; three numbered faults calibrate both local routes and
the LLVM reference in all release pipelines. The original-object driver adds
1,280 observations over complex half/float/double/x87/quad operations, wide
conversions, square roots, comparisons and bit permutations. Its boxed-half and
sret declarations match the captured ABI explicitly. Neither driver claims that
all 455 definitions executed. The 24 frozen guard/contracts, Source/value-use
interfaces and stack limits remain unchanged.
