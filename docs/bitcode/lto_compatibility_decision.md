# Bitcode And LTO Compatibility Decision

## Decision

Keep LLVM bitcode writing, bitcode parsing, ThinLTO summaries, and post-link
LTO deferred. The active implementation track remains:

```text
Zig-emitted text LLVM IR fixtures
local optimizer and verifier comparison against opt-22
native backend / AIR handoff validation for selected codegen slices
```

This is an implementation decision, not a claim that bitcode/LTO are
unimportant. Zig's LLVM path still uses bitcode for explicit bitcode output and
for linker LTO handoff. The local project does not need those artifacts to
continue optimizer and verifier work because all accepted corpus rows currently
have text IR captures and text-based `opt-22` comparisons.

Linker ownership follows the same boundary as object emission: LTO work is only
activated when Zig's linker/toolchain needs a bitcode handoff artifact from
`z_llvm`. This repository should not implement LTO linker ownership; it may
eventually produce bitcode or summary artifacts compatible with Zig's selected
linker path.

## Evidence

```text
docs/fixtures/zig_ir/manifest.tsv
docs/inventory/zig_llvm_api_inventory.md
docs/inventory/zig_llvm_pass_pipeline_inventory.md
docs/bitcode/construct_inventory.md
docs/lto/behavior_gaps.md
src/pipelines.zig
src/tests.zig lto prelink descriptor test
```

The evidence says:

```text
non-LTO release/debug rows can be validated through text IR and local pipelines
LTO pre-link pipeline descriptors exist as optimizer-surface checks
explicit bitcode output and LTO linker handoff require a writer
ThinLTO import/export requires module summary and combined-index support
no accepted source-backed row currently requires bitcode as the only artifact
```

## Proof Fixture Policy

The current proof fixture is text-IR-only:

```text
zig build test
  verifies lto-prelink-o3 and lto-prelink-oz descriptors

zig build compare-opt --
  verifies represented optimizer behavior against opt-22 on text IR fixtures
```

Do not add fake bitcode fixtures. The first bitcode fixture must be generated by
the local bitcode writer and verified with LLVM tools:

```text
llvm-dis-22 produced.bc -o -
opt-22 -S produced.bc -o -
```

## Activation Criteria

Start bitcode writer work only when at least one condition is true:

```text
a Zig LLVM-removal path needs -femit-llvm-bc without libLLVM
a Zig linker/toolchain LTO path needs a local bitcode handoff artifact from
  z_llvm
text IR is no longer enough for a source-backed compatibility test
a migration artifact must be consumed by LLVM tools that require bitcode
```

Start ThinLTO work only after bitcode output exists and a source-backed LTO row
requires summary behavior.

## Follow-Up Cycles

```text
Cycle BC1: scalar module bitcode writer for one tiny text-IR fixture
Cycle BC2: bitcode metadata and attribute encoding policy
Cycle BC3: bitcode global/alias/COMDAT encoding
Cycle LTO1: FullLTO pre-link artifact handoff to Zig's linker/toolchain through
           local bitcode
Cycle TLTO1: ThinLTO module summary inventory and writer design
Cycle TLTO2: ThinLTO import/export and WPD boundary fixtures
```

Until one of those cycles is activated, LTO remains a pre-link optimizer
pipeline descriptor plus explicit unsupported behavior for bitcode handoff,
summary indexes, import/export, WPD, CFI, and post-link optimization.
