# Zig-Emitted IR Corpus

This directory documents the fixture corpus for LLVM IR emitted by Zig's LLVM
backend. The corpus exists so parser, verifier, optimizer, and comparison work
starts from real Zig output instead of hand-written LLVM IR alone.

The first checked fixture group is `tiny_scalar`, backed by:

```text
test/zig/inputs/tiny_scalar.zig
test/zig/expected/tiny_scalar.normalized.ll
test/zig/expected/tiny_scalar.project_lowered.ll
test/zig/expected/tiny_scalar.project_optimized.ll
test/zig/expected/debug_scope_branch.reduced.ll
test/zig/expected/release_safe_safety.reduced.ll
test/zig/expected/release_safe_call_boundary.reduced.ll
```

The `src/testdata/zig_tiny_scalar.*.ll` copies exist only because Zig unit tests
embed files from inside the module root.

## Layout

```text
docs/fixtures/zig_ir/README.md
docs/fixtures/zig_ir/manifest.tsv
test/zig/inputs/<group>.zig
test/zig/expected/<group>.<kind>.ll
test/zig/captured/<group>.<mode>.<target>.ll
tmp/zig_ir/raw/<group>.<mode>.ll
```

Tracked fixture files should be normalized or project-produced outputs. Raw
Zig-emitted LLVM IR may contain machine-local debug paths and very large stdlib
support sections, so raw files are generated under `tmp/` unless a slice
explicitly sanitizes and checks them in.

The checked files under `test/zig/captured/` are stripped LLVM IR snapshots
generated by Zig's LLVM backend. They are not normalized into the local parser
subset; they intentionally preserve raw LLVM constructs that should shape future
parser, verifier, and optimizer work.

## Version Alignment Policy

The authoritative corpus must be generated from the same Zig source checkout
used by the inventories. Today the inventories point at `../ziglang`.

The current authoritative emitter for new captures is:

```text
../ziglang/build/stage4/bin/zig
0.17.0-dev.304+9787df942
../ziglang source revision 9787df9421
```

Older checked rows may retain their original emitter revision. The manifest is
the row-level source of truth for mixed-generation corpus history.

Cycle 12 refreshed selected rows against the current authoritative emitter:

```text
tiny_scalar ReleaseFast stripped capture: byte-identical to current stage4
tiny_scalar ReleaseSmall stripped capture: byte-identical to current stage4
floats_math ReleaseSmall stripped capture: byte-identical to current stage4
tiny_scalar ReleaseSafe raw capture: still too broad for checked corpus use
```

When adding or refreshing fixtures:

- [ ] Record the Zig executable version or revision used to emit the IR.
- [ ] Record the Zig source revision used to build or identify that emitter.
- [ ] Prefer a Zig executable built from `../ziglang` for authoritative rows.
- [ ] Mark rows from a released Zig binary as `legacy-bootstrap` unless the
      inventories are also pinned to that release source.
- [ ] Do not compare pass-pipeline or AIR-lowering behavior across different Zig
      revisions without a note explaining the mismatch.

## Manifest Format

`manifest.tsv` is tab-separated and has these columns:

```text
id
group
source
zig_emitter
zig_source_revision
target_arg
emitted_target_triple
optimize_mode
command
raw_ir_path
checked_ir_path
classification
inventory_links
notes
```

Classifications:

```text
parse
verify
optimizer-input
unsupported
debug-info-only
target-layout
future
legacy-bootstrap
```

A fixture can list multiple classifications separated by commas. Use
`unsupported` when Zig emits real LLVM IR that the local parser/verifier cannot
consume yet. Use `future` when the mode or feature is documented but not yet a
driver for implementation. Use `legacy-bootstrap` when the fixture was emitted
by a Zig executable that does not match the `../ziglang` source checkout used by
the inventories. Use `target-layout` when a non-host or target-sensitive row is
accepted for triple/DataLayout validation but is not yet an optimizer-input row.

## Regeneration Commands

Generate raw LLVM IR for the first scalar group with the active Zig emitter:

```sh
mkdir -p tmp/zig_ir/raw
../ziglang/build/stage4/bin/zig build-obj -fllvm -flibllvm -fno-emit-bin -femit-llvm-ir=tmp/zig_ir/raw/tiny_scalar.Debug.ll -O Debug -target x86_64-linux-gnu test/zig/inputs/tiny_scalar.zig
../ziglang/build/stage4/bin/zig build-obj -fllvm -flibllvm -fno-emit-bin -femit-llvm-ir=tmp/zig_ir/raw/tiny_scalar.ReleaseSafe.ll -O ReleaseSafe -target x86_64-linux-gnu test/zig/inputs/tiny_scalar.zig
../ziglang/build/stage4/bin/zig build-obj -fllvm -flibllvm -fno-emit-bin -femit-llvm-ir=tmp/zig_ir/raw/tiny_scalar.ReleaseFast.ll -O ReleaseFast -target x86_64-linux-gnu test/zig/inputs/tiny_scalar.zig
../ziglang/build/stage4/bin/zig build-obj -fllvm -flibllvm -fno-emit-bin -femit-llvm-ir=tmp/zig_ir/raw/tiny_scalar.ReleaseSmall.ll -O ReleaseSmall -target x86_64-linux-gnu test/zig/inputs/tiny_scalar.zig
```

The checked normalized fixture corresponds to the scalar signatures from the
current `../ziglang` `ReleaseFast` output.

## Corpus Runner

Run the accepted optimizer-input rows through the local optimizer with:

```sh
scripts/run_zig_corpus.sh
```

The runner reads `docs/fixtures/zig_ir/manifest.tsv`, preserves empty TSV
fields, and selects only rows with a checked IR path plus all of these
classifications:

```text
parse
verify
optimizer-input
```

Rows marked `unsupported` are skipped even if they are useful future optimizer
inputs. By default, the runner reads `local-pipeline=<name>` from each accepted
row's `inventory_links` field and runs that pipeline before normalizing the
result. This keeps ReleaseFast, ReleaseSmall, ReleaseSafe, and Debug rows tied
to explicit local accepted-subset aliases instead of one global pass list.

Override the manifest-selected pipeline for experiments with:

```sh
PASSES=verify,instcombine,dce scripts/run_zig_corpus.sh
```

The runner prints an execution summary with accepted, unsupported, future, and
debug-info-only row counts.

## Tiny Scalar Group

Purpose:

- scalar exported functions;
- module target records;
- aliases emitted for exported Zig functions;
- optimized integer `add nsw`;
- mode differences between Debug, ReleaseSafe, ReleaseFast, and ReleaseSmall.

Current local status:

| Mode | Status |
| --- | --- |
| `Debug` | raw IR generated successfully, but it pulls in large debug/std support and is classified as `future`. |
| `ReleaseSafe` | raw IR generated successfully, but it is still large because safety/std support remains visible; classified as `future`. |
| `ReleaseFast` | normalized scalar signature fixture and stripped captured raw fixture are checked in and classified as `parse,verify,optimizer-input`. |
| `ReleaseSmall` | stripped captured raw fixture is checked in and classified as `parse,verify,optimizer-input`; generated `tmp/` raw output remains future-only. |

Cycle 1 moved the stripped `ReleaseFast` and `ReleaseSmall` captures out of
`unsupported` by preserving exported aliases, raw function header attributes,
attribute groups, and module metadata records. Remaining checked raw corpus
parser blockers after Cycle 1:

| Fixture | First local rejection |
| --- | --- |
| `atomics_inline_asm_debug_release_fast` | Accepted as conservative inline-asm and atomic barriers; native lowering and atomic optimization remain out of scope. |

## Current Gaps

- Full raw `Debug` and `ReleaseSafe` IR are still too broad for direct checked
  optimizer-input status; reduced fixtures carry the accepted metadata and
  safety-control subsets.
- Sanitizer and trap instrumentation calls are rejected explicitly until their
  runtime ABI and lowering semantics are modeled.
- Inline asm, atomics, vector IR, COMDAT/module flag semantics, and full debug
  metadata graph interpretation remain source-backed future inputs.
